# 組員展示與分工指南

## 五分鐘操作流程

1. 在專案資料夾執行 `scripts/run.ps1`，開啟本機 8080 網站。說明預設使用 Wikipedia 與 Crossref 公開索引，不需金鑰，但要有網路；它不是全網搜尋，也不是自編教材。
2. 分別搜尋 `RSI`、`人工智慧地緣政治`、`AI 對就業的影響`，切換「概念與背景」「觀點與比較」「研究與應用」。說明所有 AI 相關議題都能輸入，結果是否切題仍需查核。若現場無結果或服務失敗，如實展示狀態，不改用示範資料冒充即時結果。
3. 點擊一筆結果標題或原文連結，開啟真正的外部網頁；再查看摘要與計數範圍，說明此模式的次數來自標題及來源摘要，不能宣稱已統計整頁全文。
4. 另行選用 HTML 抓取或主動切換「示範模式」，展示計分與網址樹，指出主頁、子頁、次數與截斷提示。到「關鍵字實驗」輸入 `RAG, Python`，說明 Boyer–Moore 與詞邊界。示範資料是自編測試內容，不代表真實外站與 Google 實測；抓取白名單也不是搜尋範圍限制。
5. 回搜尋頁切換關鍵字擴展，查看本輪新增哪些詞。沒有新增結果時如實說明，不把新增詞當成必然改善。
6. 打開「評估工作台」，展示開發題、空白評分 CSV 與 LLM 提示詞。使用現場人工判讀填寫一題，再計算前五筆相關比例；展示資料要標示為現場示例，不當成期末實測。

## 需要能解釋的程式

- A 組員：`HtmlParser`、`SafeFetcher`、`SearchEngine` 的 BFS 及網址去重。要能說明網站是圖，為什麼展示成走訪樹，以及限制深度的影響。
- B 組員：`KeywordCounter`、`Ranking` 與 PriorityQueue。要能手算一個範例、解釋詞邊界與長頁面的處理。
- C 組員：`App`、`Providers` 與 `web/`。要能說明公開索引、Brave、示範資料的差異、原文連結、摘要與 HTML 的資料範圍、模型失敗回退與 API 金鑰位置。
- D 組員：題庫、`Evaluation`、`EvaluationRunner` 與評估工作台。要能說明開發／測試分割、P@5、MRR 與公平比較。

三人組共同承擔評估，五人組可把介面與外部服務拆成兩份。建議各自完成一個有測試的修改並提交，讓 GitHub 紀錄反映真實工作；不要把自動產生的程式說成每個組員都已獨立完成與理解。

## 最後仍要由小組完成的外部事項

- 與助教確認子網址的限制範圍與字串比對規則。
- 公開索引可免金鑰實測；若要使用 Brave、Jev 或文字生成模型，另取得對應金鑰、確認額度並設定本機 `.env`。Brave 不限定教學網域；公開索引有內容覆蓋與服務可用性的限制。
- 在設定固定後蒐集 Google 與 LLM 的真實輸出，至少兩人依同一標準判讀，填入完整實驗結果。
- 選擇公開部署環境，設定 HTTPS、帳密與費用限制，再部署給指定觀眾。
- 依課程公告提交企畫、報告與原始碼，準備 12/17 Demo；本專案不自動代為提交。
